# GigBuddy v1.2.4

Released 2026-08-16.

## Built-in Presets

GigBuddy now ships 20 calibrated guitar and bass Presets as versioned JSON in
the repository. A fresh install registers the catalog and prepares the required
TONE3000 models before the TUI opens; it no longer needs a generated seed
database. If login is skipped or a remote model fails temporarily, the affected
rows remain visible as `UNAVAILABLE` and can be retried after launch.

Each row reports `PREPARING`, `READY`, or `UNAVAILABLE`. Loading an unavailable
row retries only that Preset, and a failed retry leaves the current Tone Chain
untouched. Built-in rows are read-only; **Save As** creates an editable user
copy. The installer still performs the TONE3000 login prompt and can open the
system browser.

Full workflows and failure behavior are documented in the
[built-in Preset guide](../built-in-presets.md) and
[Chinese guide](../built-in-presets.zh-CN.md).

## Preset Safety

- Bundled identity uses a stable `catalog_key`, so display-name changes and
  swaps retain the correct database row.
- User-owned rows always win a name conflict and are never inferred to be
  bundled from their name or content.
- Duplicate or uncertain editable JSON is preserved under
  `data/presets/.quarantine/` instead of warning forever or being deleted.
- Interrupted editable writes recover from the committed SQLite row on the
  next explicit refresh. Recovery-time quarantine moves now roll back with the
  surrounding reconciliation if a later Preset publication fails.
- A catalog file race restores the complete previous bundled projection only
  when no concurrent Preset write has superseded it.
- Bundled registration and editable file reconciliation use the same lock and
  the same scanned repository snapshot. Network model preparation remains
  outside that lock.
- Preparation state is scoped to normalized chain semantics and ordered
  model-to-Tone sources. A late worker cannot clear or fail a replacement that
  keeps the same model IDs but changes order, gain, bypass, or source metadata.
- Editable JSON identity includes device and ctime signals, catching equal-size
  in-place edits even when an editor restores the previous mtime. Legacy
  three-field tokens migrate on their next explicit catalog refresh.

## TUI Reliability

- Failed install-time or targeted background preparation leaves the affected rows
  retryable as `UNAVAILABLE` instead of stuck at `PREPARING`; malformed bundled
  JSON still fails bootstrap instead of being treated as a network retry.
- CLI `preset seed` and `preset bootstrap` failures list the unavailable Preset
  names as well as the total.
- A delayed Preset highlight during screen teardown is ignored rather than
  raising a Textual screen-stack error.

## Installer and Data Layout

Mutable data now defaults to `~/.local/share/gigbuddy-data`, with the install
checkout's `data` entry kept as a compatibility link. Existing custom data links
are reused. Failed upgrades restore the prior checkout and database snapshot;
an engine failure also restores the previous Eigen tree and reports incomplete
recovery if that cannot be done. Post-clone failures also run the rollback path,
while preexisting non-GigBuddy directories are rejected without modification.

The one-line installer remains interactive for TONE3000 login and installation
confirmation. Explicit `--skip-presets` permits a non-interactive automated
install, while the default path still requires the login and confirmation
flow. Failed commands include the exit status and complete shell-escaped
command. Existing command symlinks are replaced only when they resolve inside
the current GigBuddy install, and regular files are replaced only when they
exactly match the generated two-line wrapper. External links, broken links, and
user scripts that merely mention the install path are preserved. The
uninstaller now documents its options through `-h` and `--help`, applies the
same ownership rule, resolves relative internal links and physical parent
aliases, and fails closed on unresolved parent traversal.

## Install or Upgrade

```sh
curl -sSL https://raw.githubusercontent.com/ytxing/gigbuddy/v1.2.4/scripts/install.sh | bash
```

The CLI reports the same release version:

```sh
gigbuddy --version
# gigbuddy 1.2.4
```
